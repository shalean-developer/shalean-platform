# Genuine review attribution and SEO

Public cards on Home, About and Reviews share the same approved, five-star database projection. Original comments and review dates remain unchanged. Optional name (first name plus surname initial), catalog suburb and canonical service are separately permitted. Street addresses and full customer names never enter the public DTO.

Existing anonymous approvals survive the additive migration. New permission columns default to false, and existing publication context is null. No existing review's permission is expanded by the migration. Office > Reviews offers an explicit public preview, per-detail choices and permission attestation. New customer submissions and account preferences offer the same optional choices. Only content.publish can approve publication; customer consent alone does not publish a review.

The v2 approval RPC locks the review and compares the displayed comment, text consent, detail choices and preview against current values. Approval snapshots safe labels, with actor/time and Office detail-permission source. Customer withdrawal masks the corresponding label on the next server request; withdrawing text permission removes the card. Existing moderation, completion, test-data exclusion and edit invalidation rules remain intact. Old RPC signatures remain available for schema-first rollout and application rollback.

SEO: server-rendered escaped review text; semantic figure/blockquote/time; permitted canonical service links; descriptive metadata and canonical URL; visible breadcrumb matching BreadcrumbList. Selected five-star feedback is labelled as selected, and is separate from Google rating totals. No Review or AggregateRating nodes for Shalean's own testimonials: Google excludes self-serving LocalBusiness review rich results. References: https://developers.google.com/search/docs/appearance/structured-data/review-snippet and https://developers.google.com/search/docs/appearance/structured-data/sd-policies .

Validation: isolated PostgreSQL audit covers legacy anonymous approvals, exact safe context, no full-name/address disclosure, immediate withdrawal, stale permission/context rejection, unavailable details, eligibility and role boundaries. Focused rendering/API tests cover safe fields, canonical service links, escaping, explicit booleans, ownership and old-review preference updates. CI must pass critical tests, booking-core lint, typecheck, hosted Webpack build and route validation before release.

Release: apply additive migration to staging, merge application to main and verify staging; apply identical SQL to production and deploy only the scoped change from production. Validate health, public pages, permissions and SEO. Do not create or approve customer reviews as deployment fixtures. Application rollback to the preceding production release is compatible with the additive schema; no customer-data rollback is required.
